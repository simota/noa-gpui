GPU UI フレームワーク · v0.1.0 · MIT

Rust で書いて、GPU で描く。

Windows・macOS・Linux・Web で同じコードが動く、Rust 製の UI フレームワーク。 テーブルやターミナル、コマンドパレットまで揃った部品を、WebView を使わずに GPU が直接描きます。

アプリの UI を作るたび、どれかを諦めていませんか。

  1. 軽さ

    ブラウザエンジンを同梱すると、配布サイズとメモリが膨らむ。

  2. 部品

    描画は速くても、表やツリー、メニューを毎回自作することになる。

  3. 見えない必需品

    日本語入力、スクリーンリーダー、ウィンドウ位置の保存が後回しになる。

noa-gpui は、描画だけを自前で持ち、残りは実績あるライブラリに任せました。
wgpu の上の小さな 2D レンダラーに、Taffy のレイアウトと cosmic-text の文字組みを組み合わせ、OS ごとの違いは薄い層に閉じ込めています。

Design

同じコードのまま、7 つの見た目へ。

Theme::with_design を切り替えるだけで、角丸、ベゼル、配色が変わります。ライトとダーク、アクセント色、コントラストを上げる設定にも対応。

細かな調整は、CSS に似た書き方で。

型・ID・クラス・状態のセレクタ、継承、@media、変数が使える Noa Style。デスクトップではファイルを保存した瞬間に再適用されるので、ビルドし直さずに見た目を詰められます。

ブラウザの CSS と互換ではないサブセットです。未知のプロパティは無視せずエラーにします。

app.noa.css
/* 保存するとその場で反映される */
TextField, SearchField {
  border-radius: 4px;
  background-color: var(--field-fill);
}

Button.primary:hover {
  background-color: theme(accent-hover);
}

Performance

変化がなければ、描かない。

変化のないフレームは描画しないので、待機中の GPU は 0 FPS。変わった部分だけをレイアウトし直し、それ以外の描画コマンドは前のフレームから再利用します。

1 万行のリストを、1 行ずつ書き換えながらスクロール（UI ツリーの更新）
0.013ms
UiTree::prepare （レイアウトと描画リストの組み立て）の p95。GPU の描画は含みません。最適化前の 4.38 ms から 300 分の 1 以下に。
デモ全体の CPU 時間（1 万行・Metal）
1.93ms
120Hz の 1 フレーム予算 8.3 ms に余裕を残します。
10 万行テーブル、1 フレームの上限
16ms
1 フレームでも超えるとベンチマークが失敗し、CI と同じ検査（verify.sh --full）を通りません。

計測環境は Apple M1 Pro。数値と条件は docs/architecture.md に記録されています。手元では cargo bench -p ui-core --bench table で再現できます。

Essentials

地味だけど、なければ困るもの。

  • 日本語入力

    変換中の文節は太い下線で示し、候補ウィンドウはキャレットのすぐ隣に。デスクトップの IME に対応しています。

  • スクリーンリーダー

    AccessKit で OS の支援技術につなぎます。デモの全コントロールに名前があることをテストで確かめています。

  • キーボードだけで操作

    Tab でデモ全体を巡回できることをテストで検証。⌘K のコマンドパレットには、メニューバーの項目をそのまま並べられます。

  • 表示状態の保存

    列幅、分割位置、開いたタブ、ウィンドウの位置。ユーザーが整えた配置を、次の起動で元どおりに。

  • OS との統合

    macOS のメニューバー、システムトレイ、標準のファイルダイアログ、常に手前のパネルを含む複数ウィンドウ。

  • ウィンドウなしで描画

    画面を PNG に書き出せます。GPU のない CI では CPU で描画。このページの製品画像もこの機能で作りました。

Architecture

描画コマンドを境に、GPU と UI を分ける。

UI は GPU に依存しない Display List を出力するだけ。描くのは wgpu の 3 本のパイプラインです。WebGL2 を最低ラインに設計しているので、Compute Shader なしで全環境が同じ描画経路を通ります。

依存の向きは一方通行で、ui-core 以下が GPU やウィンドウに依存しないことはテストで検査しています。

Get started

3 ステップで、最初のウィンドウを。

必要なのは Rust 1.89 以上だけ。依存に加えるのは ui-platform ひとつです。

  1. 1

    サンプルを動かす

    Terminal
    git clone https://github.com/simota/noa-gpui
cd noa-gpui
cargo run -p ui-platform --example hello --features native

    部品をひととおり触るなら cargo run -p desktop --release -- --scene=catalog。

  2. 2

    コードを読む

    hello.rs
    // 部品を Widget Tree に置く
let label  = tree.insert(Some(root), Label::new("Clicked 0 times"));
let button = tree.insert(Some(root), Button::new("Click me"));

// ボタンからのメッセージに反応する
if message.source == self.button {
    self.clicks += 1;
    let text = format!("Clicked {} times", self.clicks);
    self.tree.update::<Label, _>(self.label, |l, cx| l.set_text(cx, text));
}

    全文は examples/hello.rs（約 80 行）。

  3. 3

    自分のアプリに入れる

    Cargo.toml
    [dependencies]
ui-platform = { git = "https://github.com/simota/noa-gpui", features = ["native"] }

    まだリリースタグがないので、rev = "<commit>" を足して版を固定するのがおすすめです。Web 向けには native の代わりに webgpu か webgl2 のどちらかひとつを有効にします。

FAQ

使う前に、確かめたいこと。

どのプラットフォームで動きますか？

Windows（Direct3D 12 / Vulkan）、macOS（Metal）、Linux（Vulkan / OpenGL）、Web（WebGPU、使えなければ WebGL2）です。iOS と Android は対象外です。

Web 版でできないことはありますか？

日本語入力（IME）、アクセシビリティ、ファイルダイアログは Web ではまだ使えません。Web には同梱の Inter フォントしかないため、日本語の表示もデスクトップのみです。

crates.io から入れられますか？

現在は Git リポジトリを直接依存に指定します（バージョン 0.1.0）。手順は上の「始め方」のとおりです。

ライセンスは？

MIT ライセンスです。同梱の Inter フォントは SIL Open Font License です。

見た目はどこまで変えられますか？

7 種のデザイン、ライト／ダーク、アクセント色、コントラスト強調をテーマで切り替えられます。さらに Noa Style（CSS に似たサブセット）で、自作の Widget も含めた背景・枠線・角丸・余白などを上書きできます。

品質はどうやって保っていますか？

各部品は UiTree にイベントを送って結果を確かめるテストを持ち、レンダラーは GPU で実際に描いた画素を読み戻して検証します。性能はベンチマークが 16 ms の予算を超えると失敗します。2026 年 11 月時点で、ワークスペース全体のテストは 795 件です。

まずは、ミニ OS を動かしてみてください。
