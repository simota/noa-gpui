# プロダクト分析 — noa-gpui

## 概要

noa-gpui は、wgpu の上に自前の 2D レンダラーを持つ Rust 製のクロスプラットフォーム UI フレームワーク。Windows（Direct3D 12）、macOS（Metal）、Linux（Vulkan）、Web（WebGPU、使えなければ WebGL2）で、同じ Widget Tree が動く。MIT ライセンス、バージョン 0.1.0、Git 依存で導入する（crates.io には未公開）。

根拠: `README.md`、`Cargo.toml`、`docs/architecture.md`

## 何を実現するか（機能ではなく価値）

| ユーザーの得るもの | 支える事実（確認済み） |
|---|---|
| ブラウザエンジンを同梱せず、軽いネイティブアプリの UI を Rust だけで書ける | 自前の wgpu レンダラー（Quad / Image / Text の 3 パイプライン）。WebView 不使用 |
| 表・ツリー・メニューを毎回自作しなくてよい | UI カタログ 12 グループ・87 項目（README の列挙を数えた値）。データグリッドはスプレッドシートとの貼り付け、CSV/TSV 入出力、undo/redo |
| 1 つのコードで 4 環境に出せる | 対応バックエンド表（README）。WebGL2 を最低ラインとする設計方針 |
| 大量データでも滑らか、待機中は電力を使わない | 1 万行で 1 行更新しつつスクロール: `UiTree::prepare` p95 0.013 ms（Phase 4、M1 Pro）。アイドル時 0 FPS。テーブル／デスクトップのベンチは 1 フレームでも 16 ms を超えると失敗 |
| 後回しにされがちな品質要素が最初からある | デスクトップの IME（日本語入力）、AccessKit、キーボード巡回のテスト、表示状態の保存、OS メニューバー／トレイ／ファイルダイアログ |
| 見た目を作り込める | 7 デザイン（Flat + Vibrancy / Big Sur / Liquid Glass / Aero / Metro / Fluent 2 / Noa）× ライト／ダーク、アクセント色、コントラスト強調。CSS 風の Noa Style（デスクトップは保存で即時再適用） |
| CI でも見た目を確かめられる | Headless 描画で PNG 出力（GPU がなければ CPU） |

## ターゲットユーザー

- **主ペルソナ:** Rust でデスクトップツール（エディタ、管理画面、計測・開発ツール）を作りたい中級以上の開発者。Electron/WebView の重さを避けたいが、即時モード GUI では部品・見た目・日本語入力・アクセシビリティが足りないと感じている。
- **副ペルソナ:** 同じ UI を Web（デモ・社内ツール）にも出したい開発者。
- **課題・不満:** 配布サイズとメモリ、部品の自作コスト、IME やスクリーンリーダーの後回し。
- **導入をためらう理由:** 0.1.0 であること、crates.io 未公開、Web での IME/アクセシビリティ未対応、iOS/Android 非対応、エコシステムの小ささ。
- **決定的な理由:** 実際に動くデモ（UI カタログ、ミニ OS）と、測定値・テストで裏付けられた性能と品質。
- **LP 訪問時に知りたいこと:** 何か／どの OS か／部品は足りるか／速いか／どう始めるか／制約は何か。

## 差別化ポイント

1. 描画だけを自前で持ち、レイアウト（Taffy）・文字組み（cosmic-text）は実績あるライブラリに任せる設計判断
2. macOS 標準部品に倣った豊富な部品と 7 種のデザイン
3. 計測値とテスト・ベンチマークのゲートで性能と品質を担保（`scripts/verify.sh --full` がベンチを含む）
4. 日本語 IME への具体的な対応（変換中の文節表示、候補ウィンドウ位置）

## 訴求すべき機能（優先順）

1. 4 環境・同じコード・WebView なし（何であるか）
2. 部品の豊富さ（実画面で見せる）
3. 7 デザインの切り替え（実描画で体験させる）
4. 性能（出典付きの数値）
5. 見えない必需品（IME、a11y、状態保存、OS 統合、Headless）
6. 始め方（3 ステップ、コピー可能なコマンド）
